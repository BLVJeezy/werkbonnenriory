- Billing math lives in `src/lib/billing.ts` and document line math (travel kilometres, per-line totals) in pure tested helpers in `src/lib/invoice.ts`, so quotes and invoices cannot drift; the UI computes totals live and stores only the paid amount when payment is recorded.
- External appointment proposals use splitAppointmentDays before persistence; confirmation indexes the persisted options, never a display-only transformation, so customer choice and crew notification keep identical hours.
- Every customer-driven VAT default goes through the single pure helper `vatRateForCustomer` in `src/lib/vat-number.ts`, and mail-text rules through tested helpers (urgency in `src/lib/urgent-mail.ts`, professional status in `src/lib/vat-number.ts`); screens never compute their own rate, so a new rule only has to be added once.
- Km origin = nearest active `branches` row (distance.functions.ts), else settings.base_address; one rule for all documents.
- PDF/mail/receipt extraction requests and persists supplier IBAN and printed BIC; the shared purchase normalizer supplies missing BIC from known bank codes, so import paths cannot drift.
- Manual and managed scheduled Peppol receipt share `peppol-receive.server.ts`; cron authentication precedes admin access, and message IDs deduplicate imports so background receipt never books or sends invoices.
- Mail and Peppol purchase ingestion share serialized `ingest_purchase_document` and a per-attachment ledger; Peppol upgrades preserve IDs and reviewed/payment state to prevent cross-source duplicates.
- Mail receipt eligibility uses the fixed activation cutoff in `purchase-mail-policy` both in Graph and before attachments; invoice dates come only from source documents, not mailbox timestamps.
- Bank selection reads app purchases directly; `fin_link_purchase_bank` scopes them to owned Riory BV transactions and atomically claims the payment ledger and posts only the bank leg, never a duplicate purchase document. Linked payment entries cannot be undone as loose entries.
- Split payments use `fin_split_bank_payment` and explicit per-invoice allocations capped by the unallocated bank balance; invoice updates and each balanced partial bank posting are atomic, and only a fully allocated transaction gets its completion entry.
- Waiting-account invoice allocations use `fin_allocate_waiting_bank` to reuse the split ledger atomically and replace only its bank leg with the waiting account; the original bank entry remains unchanged and residual amounts stay available.
- Partial bank journal references include cumulative allocated cents via `fin_bank_part_reference`, so each later allocation is unique while the transaction lock and existing ledger prevent reuse.
- Zero-amount bank lines are bank notices, dropped by the `fin_skip_zero_bank_tx` insert trigger so no import path (Ponto, CODA, Excel) can bring them back; paid-marked invoices settle with any open payment via `fin_split_bank_payment` type `paid`, which posts only the bank leg and never changes the invoice's paid amount.
- Crew product visibility (technicians.product_scope + crew_product_access) is enforced by products RLS and a materials trigger via crew_product_allowed(); it is not stock, saved material rows keep their own name/price.
- Werkbon SMS uses sms.functions.ts (Twilio gateway) with a unique request_key and work_order_sms history; missing credentials return a config error, never fake success.
- Subcontractor (external_planning, no login) tasks with an approved quote are closed hourly after their day by the SQL cron close_subcontractor_work_orders (subcontract_auto=true); they are invoiced only via createSubcontractInvoices from the quote's non-optional lines, so normal billing never double-counts them.
- Dashboard product sales use invoice-date net snapshots plus admin-only, read-only Simpla sales and credits; source-number deduplication prefers app snapshots, purchase failures cannot erase sales, and unmapped product IDs/descriptions retain provenance instead of guessed categories. Daily work-order revenue remains separate.
- Intervention maps use completed work-order destinations only, admin RPC checks and RLS, stable paging and conservative address keys; Google Maps renders the map (managed browser key) and geocoding goes through the connector gateway with atomic cache leases and daily budgets, premises-level results only, never fabricated coordinates; Simpla billing+delivery addresses and project addresses are included by admin request and geocoded by server-resolved refs (INTERVENTION_MAP.md).
- Attribution feed: own token, updated_at+id cursor, no unsent drafts, customer via customers.id (ATTRIBUTION_API.md).
- Map address sources fail independently and reuse an admin-only persistent Simpla snapshot, so upstream outages cannot erase historical locations.
- Insurance reports store reviewed text separately from technician notes; admin AI/save/send reuse the price-free photo PDF and info mailbox, never creating an estimate; explicitly consume the AI stream before reading its final output.
- Supplier payment edits from either purchase review or supplier management use syncSupplierPaymentMethod for all linked review/approved invoices; paid and bank-staged invoices retain their payment history, and propagation errors are surfaced.
- Manual purchase-paid flags use an admin-checked server function with explicit confirmation and paid date; they change only status/paid_at, never creating bank entries or payments, and payment exports reject paid invoices.
- Purchase bank_transaction_key is a non-unique display reference because one payment can cover several invoices; unique transaction claims and invoice allocations remain in ponto_reconciliations and fin_bank_allocations.
- Quote line discounts use the invoice snapshot convention: discounted unitPrice/amount plus originalUnitPrice and percentage; editors restore the original price, so PDF, signing, totals and quote-based invoicing never apply discounts twice.
- SEPA pain.001.001.03 always includes DbtrAgt (NOTPROVIDED when BIC is absent), uses BBA with 12 bare digits for Belgian structured references, and unique per-export message IDs; invalid fields block staging, files never prove payment.
- Dashboard date boundaries use dashboard-period.ts in Brussels time; closed months or ISO Monday–Sunday weeks feed KPIs/products and only complete calendar years enter annual comparisons. Week finance reads date-filtered, id-paged journal lines, never apportions monthly summaries.
- Purchase-invoice lines become assets only via admin-checked `fin_capitalize_purchase_line` (unique per invoice+line index, sets the line's class-2 account), so a line can never be capitalized twice.
- Loans from a purchase invoice's repayment table go through loans.functions.ts: AI reading only proposes, admin confirms; creation adds 173xxx/423xxx 'Financiering <kredietnr>' accounts via nextLoanAccounts, aflossing rows (423→550200) and 31/12 herklassering rows, so postDueLoans books them like existing loans.
- Bank undo goes through fin_undo_invoice_bank / fin_undo_purchase_bank / fin_undo_bank_allocations (claims, paid amounts and entry reverted together); undone transactions are logged in fin_audit and excluded from auto-matching so they are not relinked.
